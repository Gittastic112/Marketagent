# M03 recovery checkpoint

October 11, 2026. Recovery implementation and local drill pass. M03 remains open
for its remaining security and operator gates in the completion tracker.

## Consistency and format

Backup format 2 derives every verification record from the completed custom
PostgreSQL dump restored into an owned scratch container. The verifier has no
network, host ports or persistent volumes and uses bounded CPU, RAM and tmpfs.
Normal writers continue during backup. All public table names, counts and sorted
JSONB row SHA-256 fingerprints are included, with the PostgreSQL 16/migration
basis. Both document asset bytes and private Brief-source PDFs have per-asset
hashes, lengths and complete store totals. Missing historical stores are explicit.

The folder completes through an atomic rename. Interrupted `.partial` folders
cannot restore or enter retention. Restore validates version, allowed paths,
complete checksum coverage and inventory consistency before stopping services.
Format 1 requires explicit count-only opt-in and cannot claim content verification.
Checksums detect corruption; they do not authenticate an adversarial dump.

Restore keeps writers stopped after a failed import, content comparison or
migration. Only previously running/restarting background workers resume. Retention
is off by default, preserves at least one verified owned format-2 folder and skips
unrelated, invalid, legacy, partial and linked directories. No normal backups were
pruned. The portable Python helper works without changing blocked host tooling.

## Evidence

- Nine metadata tests plus 15 shell-orchestration tests cover complete inventories,
  equal-count corruption, omitted private PDF bytes, duplicate records, paths,
  symlinks, checksum coverage, old/unknown formats, active/disabled workers,
  failed restores, interrupted backups and owned scratch cleanup.
- Seventeen backend guard tests reject fixture seed/clear/verify/write actions
  before opening a database session when any disposable target boundary is missing.
- The actual PostgreSQL drill uses a new internal-network, portless Compose
  project with tmpfs database storage. It verifies the actual data directory's
  filesystem before adding any fixture. APP_ENV, database name, host and explicit
  disposable marker all guard fixture mutations.
- On October 11 the completed dump held **2 source rows** while the concurrent
  writer grew the live test database to **101**. Restore matched all 109 table
  inventories/content fingerprints before the unchanged migration head upgrade.
- Original public and private PDF bytes, private findings, exact analyst receipt
  references and portfolio holding/transaction relationships survived. All inputs
  are **Mock Data**. The normal database and source worker were untouched.
- Measured restore verification: **10 seconds**; complete local drill: **33 seconds**.
  This is a small fixture on this machine, not a promised recovery time.
