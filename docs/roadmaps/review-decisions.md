## Returned review design decisions

These defaults apply the user's preservation, privacy and truthful-UI instructions.
The [intake receipt](../../data/reviews/code-review-intake-20261115.json) pins the reports;
the [roadmap](product-roadmap.md#review-repair-sequence) owns sequencing. No immediate
user answer is needed for the ten-set release follow-up or R2/R3 source fixes. Historical data rewrites remain outside that authorization.

| Review question | Adopted design or explicit boundary |
|---|---|
| 1 · Brief acknowledgement | Acknowledge the displayed snapshot's coverage endpoint, not unseen events through click time. Preserve old snapshots; change the deliberate old test with a regression for intervening events/failures |
| 2 · Reporting currency | Preferences affect future calculations. Preserve each snapshot's original currency; withhold mixed-currency arithmetic. Historical conversion needs a separately reviewed basis and retained originals |
| 3 · Benchmark freshness | Start with the existing five-calendar-day market-price ceiling as an explicit conservative policy, applied to quote and FX dates. Disclose age and method; do not infer a trading calendar or treat unknown timing as fresh |
| 4 · Correction origin | Preserve original values and edit history. Manual overrides remain User Assumptions; source-backed correction requires exact asset/revision/locator, units, period and explicit review. Do not relabel legacy records by guess |
| 5 · PDF continuation | A bounded extract-more-pages action reuses the retained asset, hash/parser/page identity and Processing Run. Re-upload remains deduplicated; no second permanent byte copy |
| 6 · Missing workbooks | Disclose absent original bytes; offer optional hash-verified reattachment. Do not reconstruct a supposed original from extracted cells |
| 7 · Legacy shared research | Owner-scope new private research. Existing global evidence-ledger/variant-perception rows need read-only inventory and an explicit sharing/ownership decision before reassignment; do not infer an owner |
| 8 · Private run metadata | Owner-only in ordinary research views. Shared public ingestion remains visible; an operator-wide private-run view needs explicit authorization and audited purpose |
| 9 · Legacy recovery | Reject known destructive legacy transitions before writes. Support depends on a preserving conversion and separately scoped rehearsal; no old backup is declared safe or disposable from its age |
| 10 · Recovery target | Derive and verify the existing project's ordered Compose files, images, volumes and writers. This is technical discovery, not a request for the user to supply secrets |
| 11 · Commit privacy | Exclude raw chat links and personal addresses. Before future publication verify a suitable private commit identity; account changes or rewriting public history are separate choices |
| 12 · Interrupted AI | Persist an attempt before sending. Show pending or unknown outcome after interruption; never silently resend. A retry is explicit and retains its predecessor |
| 13 · Valuation acknowledgement | Allow reviewed/no numerical change with an exact version/event token, reason and retained receipt. Reject stale acknowledgements; numerical changes create a new version |
| 14 · History exports | Preserve raw stored inputs/outputs/warnings and separately label current interpretation. Read reconciliation must not silently become an exact historical export |
| 15 · Financial-sector models | Enforce the existing FCFF hard block consistently. No new exception or alternative methodology is introduced by this review |

Question 7 can require an owner choice before historical ownership changes;
questions 6 and 11 need input only if original-file recovery or account/history
changes are requested. Unknown evidence remains unavailable. Continue independent
repairs without treating these conditional choices as answered. Legacy conversion
and populated recovery also need the explicit scope required by Operations.

## Revisit a choice

Identify the exact decision, evidence, input versions and scope. Add a dated
superseding decision with rationale, affected records and uncertainty; preserve
prior receipts. Recheck current source and authorization before applying a material
change. A decision alone does not close an acceptance gate.
